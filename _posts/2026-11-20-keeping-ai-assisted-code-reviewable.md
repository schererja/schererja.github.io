When I started using Claude Code alongside GitHub Copilot, it made it easier to move some side-project ideas forward. I still wanted to know what was changing and be able to back out of a direction that turned out to be wrong. Git was the part of that workflow I already knew how to rely on.

## Give the change a place to live

I like doing the work on its own branch and committing as I go. That gives me a record of decisions I can inspect and a way to return to a known state if an experiment runs too far. It also makes it easier to consider one piece of the work at a time.

## Read the logic before merging

When I open a pull request, I still want to read the changes and figure out whether the behavior makes sense. Another review tool can help catch something I missed. I’m still responsible for understanding the code and deciding whether it belongs in the project.

I’ve also had questions about how organizations treat ownership of work created with these tools. That’s something I want to understand as I use them more. The immediate part I can control is what I put into the tool and how carefully I review what comes back.
